# Cove — Wellness Studio & Retreat Website Template

**Template 10 — Cove** is a small, premium, production-ready website template for a
wellness studio, spa or retreat brand. It is a *frontend template*: static, editable
and deployable in minutes. There is no backend, no CMS and no booking engine.

Cove itself is a fictional brand. Every treatment, retreat, price, article and
practitioner in this repository is demo content.

---

## Tech stack

| | |
|---|---|
| Framework | Next.js 16 (App Router, Server Components by default) |
| Language | TypeScript (strict) |
| Styling | Tailwind CSS v4, with CSS custom properties as design tokens |
| Icons | `lucide-react` |
| Fonts | Fraunces (editorial serif) + Inter (UI), via `next/font/google` |
| Dependencies | That is the whole list — no UI kit, no state library, no animation library |

Everything is statically generated. There are no API routes, server actions,
database calls or runtime auth.

## Routes

| Route | Description |
|---|---|
| `/` | Homepage — hero, philosophy, treatments, approach, retreats, practitioners, journal, CTA |
| `/treatments` | All six treatments |
| `/treatments/[slug]` | Treatment detail (6 statically generated pages) |
| `/retreats` | Three retreat experiences |
| `/journal` | Journal index with a lead article |
| `/journal/[slug]` | Article detail (6 statically generated pages) |
| `/about` | Story, principles, practitioners, studio facts |
| `/contact` | Details, opening hours and a validating demo form |
| `404` | Not-found page (`noindex, nofollow`) |

Also generated: `/sitemap.xml`, `/robots.txt`, `/manifest.webmanifest`,
`/opengraph-image` (1200×630 PNG, built at compile time).

## Project structure

```
src/
  app/
    layout.tsx            Root layout, fonts, metadata, no-flash theme script
    page.tsx              Homepage
    globals.css           Design tokens + base styles  ← colours live here
    not-found.tsx         404
    opengraph-image.tsx   Social share card
    sitemap.ts robots.ts manifest.ts
    treatments/ retreats/ journal/ about/ contact/

  content/                ← ALL editable marketing copy
    types.ts              Content types (Treatment, Retreat, Article, Artwork…)
    site.ts               Brand name, URL, description  ← change the URL
    navigation.ts         Header, footer and social links
    home.ts               Every word on the homepage
    treatments.ts retreats.ts journal.ts about.ts contact.ts

  components/
    layout/               SiteHeader, SiteFooter, ThemeToggle
    ui/                   Artwork, Button, SectionHeading, Breadcrumb
    wellness/             TreatmentCard, RetreatCard, ArticleCard, PractitionerCard
    forms/                ContactForm

  lib/seo.ts              Per-page metadata builder (canonical, OG, Twitter)
```

No significant marketing copy lives inside page components. To rebrand Cove you
should only need `src/content/` and the token block in `src/app/globals.css`.

## Customising

### 1. Change the site URL (required before deploying)

`src/content/site.ts` ships with a **placeholder**:

```ts
url: "https://cove.example.com",
```

Replace it with your real domain. Canonical URLs, `sitemap.xml`, `robots.txt`
and all Open Graph tags are derived from this one value.

### 2. Edit the content

Everything is typed, so a typo becomes a build error rather than a broken page.

- **Add a treatment** — append to the array in `src/content/treatments.ts`. The
  listing page, detail page, related-treatment logic and sitemap all pick it up.
- **Add an article** — append to `src/content/journal.ts`. Body copy is typed
  sections (`{ heading, paragraphs[] }`), so no Markdown dependency is needed.
- **Change navigation** — `src/content/navigation.ts`.
- **Change contact details / hours** — `src/content/contact.ts`.

### 3. Change the colours

All colour lives in two blocks at the top of `src/app/globals.css`: `:root` for
light and `[data-theme="dark"]` for dark. Tailwind utilities (`bg-bg`,
`text-ink-soft`, `border-line`, `text-accent`…) map onto them through
`@theme inline`, so editing a token re-skins the whole site — including the
artwork.

The dark palette is authored separately (deep moss and brown-black), not
generated by inverting the light one. Keep it that way if you re-theme.

### 4. Change the typography

Fonts are declared in `src/app/layout.tsx` via `next/font/google` and exposed as
`--font-fraunces` / `--font-inter`. Swap the imports, keep the CSS variable
names, and the rest of the site follows. Headings use the `.serif` class defined
in `globals.css`.

### 5. Replace artwork with real photography

The template ships with seven locally drawn SVG motifs (`ripple`, `botanical`,
`stone`, `horizon`, `bloom`, `mineral`, `flow`) in five natural tones — so there
are **no stock photos and no external image requests**.

Every content entry references artwork like this:

```ts
artwork: {
  motif: "stone",
  tone: "sage",
  alt: "Stacked smooth stone forms resting in soft sage light",
}
```

To use a real image, drop the file in `public/images/` and replace that entry:

```ts
artwork: {
  image: "/images/deep-rest.jpg",
  alt: "A treatment room with linen and low afternoon light",
}
```

**No component changes are required.** `<Artwork>` renders an optimised
`next/image` for `image` entries and the SVG motif otherwise. Always write a
meaningful `alt`.

> Note: `next.config.ts` sets `images.unoptimized: true` because the template has
> no photography of its own. Remove that line once you add real images and want
> Next.js to optimise them.

### 6. Theme switching

`<html data-theme>` is the single source of truth. A tiny blocking script in
`layout.tsx` sets it before first paint — reading `localStorage`, falling back to
the OS preference — so there is no theme flash. `ThemeToggle` subscribes to that
attribute with `useSyncExternalStore` and flips it. No provider, no context, no
theme library.

## Deploying

The build output is fully static, so any host works:

```bash
npm run build && npm start     # Node server
```

- **Vercel** — import the repository; no configuration needed.
- **Netlify** — build `npm run build`, use the Next.js runtime.
- **Static file hosts (GitHub Pages, S3, Cloudflare Pages)** — uncomment
  `output: "export"` in `next.config.ts` and deploy the generated `out/`
  directory.

Before you deploy: change `site.url`, replace `public/icon.svg`, and review the
demo notice in `src/content/site.ts`.

## Demo-only limitations

This is a template, and it is honest about what it does not do:

- **The contact form does not send anything.** It validates properly (required
  fields, email format, minimum message length, focus moved to the first invalid
  field) and then says: *"This is a template demo. No message was sent."* Wire it
  to your own provider — Formspree, Resend, a serverless function — before launch.
- **There is no booking, availability, reservation or payment logic.** Every
  treatment and retreat CTA opens a conversation on `/contact`.
- **No accounts, no cart, no orders, no analytics.**
- **All content is fictional.** The practitioners are characters, not real people;
  no qualifications or credentials are implied. Prices are placeholders.
- **No medical or therapeutic claims are made**, and none should be added without
  proper review.
- **Social links point at placeholder URLs** in `src/content/navigation.ts`.

## Accessibility

Built in: skip link, semantic landmarks, exactly one `<h1>` per page, ordered
heading levels, keyboard-operable navigation, visible focus rings, `aria-current`
on the active nav item, `aria-expanded`/`aria-controls` on the mobile menu with
Escape-to-close and body scroll locking, labelled form fields with `aria-invalid`
and `role="alert"` errors, labelled artwork, and a `prefers-reduced-motion` block
that disables transitions.

This has been tested with automated checks and by hand in a browser. It is *not*
a claim of formal WCAG conformance — audit it against your own requirements
before launch.
